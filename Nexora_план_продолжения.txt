===== #10 РЕАЛЬНАЯ ОПЛАТА FRIDE — ГЛАВНОЕ =====

ДИЗАЙН ПОТОКА (решение уже принято, не менять):
 1. Клиент генерирует id платежа pay_<ts>_<rand>.
 2. POST /api/fride/create → сервер (Vercel) создаёт счёт во Fride,
    возвращает payment_url. Сервер НЕ хранит ничего в blob — статус
    берём ЖИВЬЁМ из Fride через invoice/getInfo. (Почему: api/save.js
    перезаписывает nexora_payments целиком, без слияния — нельзя
    хранить там серверные записи.)
 3. Клиент открывает payment_url в новой вкладке, поллит
    GET /api/fride/status?id=<id> каждые 3 сек (таймер fridePollTimer),
    пока не paid / failed / timeout.
 4. webhook /api/fride/webhook — опционально, только для Telegram-
    уведомления об оплате. На статус-поллинг не влияет.
 5. Если FRIDE не настроен (нет ключей) → сервер отвечает
    {success:false, error:'FRIDE_NOT_CONFIGURED'} → клиент падает в
    тестовый режим с тостом «Fride не настроен, оплата тестовая».

ФАЙЛЫ КОТОРЫЕ НАДО СОЗДАТЬ:
 a) api/fride/create.js (Vercel, POST):
    - тело: {order_id, amount, currency:'RUB', method, comment, success_url, fail_url}
    - env: FRIDE_MERCHANT_ID, FRIDE_API_KEY; если нет → {error:'FRIDE_NOT_CONFIGURED'}
    - Fride: POST https://api.fride.io/invoices/create
      headers: X-Api-Key: <API_KEY>
      body: {merchant_id, order_id, amount: <float>, currency, comment?, success_url?, fail_url?}
    - ВАЖНО: имя поля с ссылкой на оплату неизвестно — парсить защищённо
      из любых вариантов: payment_url, url, link, invoice_url, pay_url,
      redirect_url, data.payment_url и т.п.
    - ответ: {success:true, payment_url, id: order_id}
 b) api/fride/status.js (Vercel, GET):
    - GET ?id=<order_id>
    - Fride: GET https://api.fride.io/invoice/getInfo?merchant_id=<MID>&order_id=<id>
      headers: X-Api-Key
    - маппинг статуса: 'paid' → 'paid'; остальные вернуть как есть.
    - ответ: {success:true, status}
 c) api/fride/webhook.js (Vercel, POST):
    - подпись: HMAC-SHA256 hex от ksort'нутого JSON верхнего уровня
      (кастомные поля кастуются в объект), encode JSON_UNESCAPED_UNICODE
      | UNESCAPED_SLASHES; ключ = FRIDE_API_KEY (секрет мерчанта).
      Заголовок подписи проверять среди: x-signature, signature, x-hmac-sha256.
      Если не совпало → 403. Не ронять на ошибках парсинга.
    - при status=paid → отправить Telegram-уведомление «💳 Оплата <сумма> ₽»
      организатору (chat_id из nexora_settings в blob, токен из env или запасной).
    - ВСЕГДА отвечать 200 быстро, даже если что-то упало.

ВАЖНЫЕ НЮАНСЫ (уже выяснены)
------------------------------------------------------------
• Vercel Blob: get() требует {access:'private', useCache:false};
  put() требует allowOverwrite:true; cacheControlMaxAge:60 — иначе CDN
  держит месяц.
• Файл:// демо-режим работает без сервера (localStorage).
• api/save.js мержит только registrations/join_requests/support_tickets;
  остальные ключи перезаписывает целиком. nexora_payments НЕ мержится.
• Админ-токен (nexora_admin_token) НИКОГДА не синкается на сервер —
  только localStorage.
• Бот Telegram: @Nexora1s_bot, токен выше. Chat ID бот отвечает на /id.
• В админке нет showToast — там alert()/confirm().
